# 知识重组指标计算说明

## 一、理论基础

### 1.1 知识重组理论渊源

创新经济学的一个核心命题是：**创造即组合**（Schumpeter, 1934）。熊彼特指出，"生产意味着把我们力所能及的要素和力量按我们的意愿组合起来...生产其他事物...意味着按不同的方式组合这些材料和力量"。这一洞见奠定了技术创新研究的基础——企业的新颖性源于既有知识元素的重新组合。

此后，Galunic & Rodan (1998)、Hargadon & Sutton (1997)、Henderson & Clark (1990) 等学者的研究进一步表明，企业的创新能力很大程度上取决于其**知识重组能力**（recombinant capabilities）——即将现有技术重新组合以产生技术创新成果的能力。

### 1.2 知识重组的二元性

Carnabuci & Operti (2013) 的重要贡献在于识别出重组能力的**两个维度**：

| 维度 | 名称 | 含义 |
|------|------|------|
| **Recombinant Creation（重组创造）** | 创造新组合 | 企业创造出技术组合的新组合方式，即产生**企业从未使用过**的技术组合 |
| **Recombinant Reuse（重组利用）** | 重用已有组合 | 企业重新配置已知的技术组合，即**重复使用**企业历史上已有的技术组合 |

### 1.3 本脚本的实现

本脚本实现了 Carnabuci & Operti (2013) 提出的两个核心指标：

- **RC（重组创造）**：衡量企业当年专利中，**新组合**占总组合的比例
- **RR（重组利用）**：衡量企业在历史中**重复使用**技术组合的程度

这两个指标均基于专利的 IPC（国际专利分类）代码构建的技术组合来计算，支持不同的 IPC 粒度（3位/4位）和不同的时间窗口（lag3/lag5/lag7）。


## 二、核心计算逻辑

### 2.1 IPC位数说明

本脚本当前支持基于以下IPC位数计算知识重组指标：


| IPC位数  | 示例               | 粒度  | 说明    |
| ------ | ---------------- | --- | ----- |
| **3位** | F16, B03, H01    | 中等  | IPC大类class |
| **4位** | F16H, B03C, H01M | 最细  | IPC小类subclass |


> 如需添加其他位数（如5位），只需在脚本顶部的 `IPC_DIGITS` 列表中添加，详见 [八-1 配置参数](#八代码配置说明)。

### 2.2 知识组合的生成

**步骤1：提取IPC代码**

从专利中提取所有指定位数的IPC代码（不含主/附分类区分，截取分类号主号部分）：

```
专利A的IPC: F16H1/34; B03C3/02; H01M2/10; F16H3/00

提取3位码: {F16, B03, H01} (3个，唯一化后)
提取4位码: {F16H, B03C, H01M} (3个，唯一化后)
```

> 注：`extract_ipc_digits` 使用 `set()` 对截断后的IPC码去重，若不同IPC截断到相同位数则合并为1个。

**步骤2：两两组合生成知识组合**

使用组合公式 C(n,2) = n(n-1)/2 生成所有两两组合：

```
IPC 4位码集合: {F16H, B03C, H01M}

组合数量 = 3 × (3-1) / 2 = 3 个组合

生成的组合（按字典序排序，小号在前）：
1. B03C - H01M
2. B03C - F16H
3. F16H - H01M
```

> 组合格式：`"技术1-技术2"`，其中技术1 < 技术2（字典序），保证同一组合只有唯一表示。

### 2.3 指标计算

**重组创造 (Recombinant Creation, RC)**

```
重组创造 = 新颖组合数 / 总组合数

新颖组合 = 当前专利的组合 - 历史组合池（时间窗口内）
```

**重组利用度 (Recombinant Reuse, RR)**

> 这是论文中的关键细节：**重用度只计算历史中出现过的组合**

```
重组利用 = Σ(n+1) / m

其中：
- n: 该组合在历史中出现的次数
- +1: 加上当前专利这一次
- m: 历史中出现过的组合数量（没出现的不参与计算）

对于当前专利的每个组合：
- 历史中出现 n 次 → 贡献 (n + 1)
- 历史中没出现 → 不参与计算

含义：
- 重组利用 ≥ 1：表示该组合是历史中重复出现过的
- 如果所有组合都是新组合 → 重组利用 = NaN（无法计算）
```

> **论文公式来源**：Carnabuci & Operti (2013) SMJ, p.782-785
>
> 论文中 RR 的定义是：分子为历史重复组合的累计使用次数，分母为当前专利的总组合数。
> 这里的分母 m 等价于当前专利中"历史出现过的组合数"。

**计算示例：**

```
专利的组合: [A, B, C]
- A: 历史出现 2 次 → 计 2+1 = 3
- B: 历史出现 1 次 → 计 1+1 = 2
- C: 没出现过 → 不参与

重组利用 = (3 + 2) / 2 = 2.5
（分母是2，因为只有A和B在历史中出现过）
```


## 三、计算示例

### 示例数据

```
专利A的4位码: {F16H, B03C, H01M}
→ 组合: {B03C-F16H, B03C-H01M, F16H-H01M} (共3个)

历史组合池(前3年)及出现次数:
- B03C-F16H: 出现过 2 次
- B03C-C12N: 出现过 1 次
- B03C-G01N: 出现过 1 次
- F16H-H01M: 出现过 3 次
```

### 计算过程

```
总组合数 = 3

新颖组合 = {B03C-F16H, B03C-H01M, F16H-H01M} - {B03C-F16H, B03C-C12N, B03C-G01N, F16H-H01M}
         = {B03C-H01M}  (只有1个是新组合)
新颖组合数 = 1

重组利用计算（只有历史出现过的才参与）：
- B03C-F16H: 历史出现2次 → 计 2+1 = 3，参与计算
- B03C-H01M: 新组合 → 不参与计算
- F16H-H01M: 历史出现3次 → 计 3+1 = 4，参与计算

重组利用 = (3 + 4) / 2 = 3.5
（只有B03C-F16H和F16H-H01M参与，因为它们在历史中出现过）

重组创造 = 1 / 3 ≈ 0.333
```

### 重要说明

```
重组利用 ≠ 1 - 重组创造

原因：
- 重组创造 = 新组合数 / 总组合数 = 1/3 ≈ 0.333
- 1 - 重组创造 ≈ 0.667
- 重组利用 = Σ(n+1) / m（只计算历史中出现的组合）

两者不是简单的互补关系！

特别说明：
- 重组创造 ∈ [0, 1]
- 重组利用 ∈ [1, +∞)（因为 n+1 ≥ 1）
- 如果所有组合都是新的 → 重组利用 = NaN
```


## 四、时间窗口


| 时间窗口 | 含义  | 计算2020年指标时          |
| ---- | --- | ------------------- |
| lag3 | 前3年 | 使用2017-2019年所有专利的组合 |
| lag5 | 前5年 | 使用2015-2019年所有专利的组合 |
| lag7 | 前7年 | 使用2013-2019年所有专利的组合 |


> lag3 / lag5 / lag7 可通过 `TIME_WINDOWS` 配置参数同时计算。


## 五、数据预处理

### 5.1 专利ID提取逻辑

每行专利优先使用干净的 `公开公告号_clean`（去除末尾字母后缀 A/B/U/S），因为同一个专利可能因申请阶段不同而产生多个公开公告号。

### 5.2 去重逻辑

在分块读取时，同一块内按 `股票代码 + 公开公告号_clean` 去重。

### 5.3 设计专利过滤

读取完成后，若 `专利类型` 列包含"设计"字样，该行将被移除。

### 5.4 畸形行处理（`_CSVChunkReader`）

使用 Python 内置 `csv` 模块逐行读取大CSV，处理以下异常：

- **列数不匹配**：若某行列数与表头不一致，跳过该行
- **解码失败**：通过 `errors='replace'` 替换不可见字符

全文件跳过的总行数在读取完成后通过 `chunk_reader.skipped` 属性获取。


## 六、输出指标说明

### 6.1 指标命名规则

```
指标 = [类型]_[IPC位数]_[时间窗口]

类型：
  - avg_rc:  重组创造 (Recombinant Creation) 均值
  - avg_rr:  重组利用 (Recombinant Reuse) 均值

  - avg_novel: 平均新颖组合数

IPC位数：
  - 3d: IPC 3位（小类）
  - 4d: IPC 4位（小组）

  - lag3: 前3年
  - lag5: 前5年
```

## 八、代码配置说明

### 8.1 可配置参数

```python
IPC_DIGITS    = [3, 4]       # IPC位数列表，支持扩展
TIME_WINDOWS  = [3, 5, 7]    # 时间窗口，可修改
CHUNKSIZE     = 100_000      # 分块读取行数
ENCODING      = "utf-8-sig"  # 文件编码
```

### 8.2 添加新的IPC位数

如果需要添加其他IPC位数（如1位或5位），只需修改 `IPC_DIGITS` 列表：

```python
IPC_DIGITS = [3, 4, 5]   # 添加5位IPC
```

其余代码无需改动，将自动为新增位数生成对应指标。

### 8.3 `n_patents` 的合并逻辑

当多个IPC位数的结果合并时，`n_patents` 取各位数计算结果的最大值，而非简单合并。这是因为同一专利在同一IPC位数下只计数一次，取最大值反映了最细粒度下的专利计数。

## 九、注意事项

### 9.1 单个IPC码的专利

如果专利只包含1个唯一的N位码，则无法生成两两组合：

```
专利B的4位码: {F16H}
→ 组合数 = 0
→ 重组创造 = NaN (无法计算)
→ 重组利用 = NaN (无法计算)
```

### 9.2 两个IPC码的专利

如果专利恰好包含2个N位码，则只有1个组合：

```
专利C的4位码: {F16H, B03C}
→ 组合: {B03C-F16H} (共1个)

如果该组合在历史中出现2次：
  重组利用 = (2+1) / 1 = 3

如果该组合是全新的（历史中没出现过）：
  重组利用 = NaN（没有历史数据，不参与计算）
```

### 9.3 早期年份缺失

- lag7 要求有7年前的数据，1985-1991年的数据可能缺失lag7指标
- lag5 要求有5年前的数据，1985-1989年的数据可能缺失lag5指标
- lag3 要求有3年前的数据，1985-1987年的数据可能缺失lag3指标

### 9.4 IPC码截断去重导致的组合缺失

`extract_ipc_digits` 使用 `set()` 对IPC码进行去重，当不同IPC码截断到指定位数后相同时会被合并：

```
原始IPC: A61K31/35; A61K35/78
→ 截断到4位: ['A61K', 'A61K']  ← 两个码截断后相同
→ set去重: {'A61K'}             ← 合并为1个
→ 组合数 = 0（元素不足2个）
→ 重组创造 = NaN
→ 重组利用 = NaN
```

**这是正常情况**，不会产生自组合。`safe_mean` 自动跳过 NaN 值，因此公司年度均值只基于有效专利计算。

### 9.5 跨块重复无法检测

去重在每个读取块内独立进行（`drop_duplicates`），不同块之间的相同记录不会被检测和合并。若原始数据中同一专利出现在不同块中，会被保留多条记录。
